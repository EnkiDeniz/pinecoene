**Status:** Curated Studio V1 implementation approach  
**Supersedes:** v0.2 where it treated the Locket as the primary public product

## The first sight

Pinecœne should not introduce itself as a gift box. It should introduce itself as a living instrument whose form already bears consequence. The gateway therefore gives PCN-0002 the stage, identifies that six phases are sealed and one remains OPEN, and makes **Enter the Studio** the unmistakable primary act. **Open an Offering** remains visible, but downstream.

The target feeling is archaeological precision rather than spectacle for its own sake: black space, thin instrument rules, committed gold, event-local evidence blue, neutral structural Edge and cool OPEN light. There is no ambient galaxy fog. Every visible particle has semantic standing.

## Visual grammar

- **Owner world:** deep black and charcoal with compact rails, exact telemetry and generous object stage.
- **Artifact voice:** Newsreader, used for titles, admitted record and inspection prose.
- **Instrument voice:** Geist, used for controls and navigation.
- **Provenance voice:** monospaced typography, used only for hashes, phase numbers, source anchors and timing.
- **Gold:** owner commitment, selected action and admitted Solid.
- **Evidence blue:** only Return event loci and causal evidence.
- **Cool OPEN:** capacity, permeable edge and unresolved path.
- **Neutral Edge:** Bag, relation capacity and inactive structure.

The supplied Studio and Becoming references set the density, object scale and instrument character. V1 evolves them into one coherent product system rather than reproducing prototype screens verbatim.

## Composition

Desktop uses an object-plus-inspector instrument. The stage is always dominant; the inspector changes task while the Fold remains spatially stable. Becoming expands into an immersive stage with phase jumps, causal caption and scrub controls.

Mobile does not compress a desktop rail. It uses a full-stage object, horizontally traversable mode rail and task-focused bottom-sheet inspector. Persistent actions remain reachable at the bottom. At 390 × 844, the form keeps at least 55% of the initial visual field.

## Interaction law

1. A visitor first sees a formed consequence, not a form to fill.
2. Record inspection precedes Admission.
3. Admission and Recognition are separate owner acts.
4. Geometry recompiles immediately and deterministically after an owner decision.
5. Becoming reveals causes in time; Fold reveals standing at rest.
6. Expression and Address operate presentation and orientation without rewriting topology.
7. Offering Preview and recipient Witness render the exact same serialized package.
8. A Return stays recipient-authored and browser-local until the owner simulates a disposition.
9. Successor docking creates lineage without claiming publication.

## Sound, motion and access

Sound is off by default and starts only from a direct user gesture. The Studio does not require sound to communicate causal standing. Reduced motion disables continuous rotation and turns Becoming into seven explicit semantic steps. Keyboard focus is visible; form rotation supports arrow keys; all inspector states have ordinary semantic controls; and a text anatomy fallback preserves the product when WebGL is unavailable.

## Engineering shape

Next.js App Router renders the route shell and canonical fixture data. React controls owner state and accessible instruments. Lit owns custom-element boundaries. Direct Three.js renders the Fold, Locket and Vital Sign independently. Dexie preserves additive local custody. JCS plus SHA-256 freezes identities. Ajv remains available at serialization boundaries. Heavy Three.js code is dynamically loaded by the client wrappers so the gateway text and actions do not wait for WebGL.

The deterministic compiler is renderer-neutral. UI code cannot invent topology. Renderer code cannot see rejected/private candidates. Recipient code receives a pre-projected package, not an owner archive.

## Release rule

Build and visual QA occur on an isolated branch and protected Vercel Preview. Production remains on its current deployment until the candidate has a clean exact SHA, passing golden and journey tests, reference-to-implementation visual comparison, privacy inspection and hosted browser verification. The current production deployment remains the immediate rollback target through promotion.
