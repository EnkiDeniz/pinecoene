## 0 · The approach change

Version 0.3 was correct about deterministic form, semantic geometry, object-first experience, and the separation of Studio, Fold, Locket, and Vital Sign. Its public composition is now stale: the production Door is Genesis-led, not a PCN-0002 Studio gateway.

The deeper correction is methodological.

We should not design a more complete generic Pinecœne machine and later search for content that fits it. The next build should begin with one exact, consequential, real-life example and carry it through the entire reconstruction loop:

```text
ordinary source projection
    ↓
Reader candidates
    ↓
human admission
    ↓
admitted record
    ↓
Pinecœne normal form
    ↓
Fold and Becoming projections
    ↓
trace-linked authored projection
    ↓
Offering and Locket
    ↓
Encounter and Return candidate
    ↓
owner disposition
```

Where the example contains both an intended projection and world-facing evidence, it also supports:

```text
P_intended + P_as-built → typed residual Δ
```

That loop is the product proof. The public site can explain the theory later. First, the object must demonstrate it.

## 2 · The next proof

### 2.1 One case before a platform

The next implementation unit is a **Reconstruction Case**, built from an owner-supplied example. It is not initially a public Work and not automatically a new canonical specimen.

Its purpose is to prove, visibly and technically, that:

1. an ordinary text or artifact can be treated as a projection without pretending that its full interior is recoverable;
2. multiple declared readings can surface candidate structure and uncertainty;
3. a human can `admit`, `rewrite_admit`, `leave_open`, `reject`, or `withhold_from_record` per candidate;
4. the admitted record compiles deterministically into a renderer-independent normal form;
5. several lawful projections can be generated from the same normal form without changing its identity;
6. every governed claim in those projections can trace back to admitted source coordinates;
7. intended and observed projections can be compared through a typed residual when evidence permits;
8. a recipient can receive a bounded projection through a Locket without receiving hidden owner material;
9. a Return remains a candidate until the owner makes a separate disposition.

The first complete implementation proof requires Reconstruction, at least one trace-linked governed projection, and Passage through Offering, Locket, Encounter, and bounded Return. Multi-beam tomography is used when separately authorized source projections exist. The intended/as-built residual remains conditional and is never a prerequisite for Passage.

### 2.2 Eligibility for the first case

The example is implementation-eligible only when it has:

- an exact or explicitly sanitized supplied source;
- a named owner or authorized steward;
- a bounded reconstruction question;
- declared source ownership and processing permission;
- stable source coordinates or an honest coordinate derivation method;
- a clear private, protected, sanitized, or public boundary;
- enough semantic material to produce non-trivial candidate structure;
- explicit acknowledgement of material that remains inaccessible or human-attested;
- and, for an intended/as-built comparison, attributable world-facing evidence.

An unavailable-only or referenced-only source may be preserved as lineage, but it returns `qualified_with_missing_material` and cannot become the implementation source until exact or explicitly sanitized material is supplied.

A polished example is not necessarily the best first case. A useful first case has inspectable structure, genuine uncertainty, and consequences that can be checked.

### 2.3 Standing ladder

```text
received material
→ qualified private case
→ owner-approved protected Preview
→ optional sanitized Example
→ separately admitted public Work
```

Each arrow requires an explicit decision. None is automatic.

## 3 · Reconstruction envelope

Every case begins with a versioned **Reconstruction Envelope**. It binds the question, sources, readings, decisions, compiler profile, projections, evidence, permissions, and residual without claiming that the inaccessible interior has been recovered.

The envelope contains:

| Part | Function |
|---|---|
| Case manifest | identity, owner, question, dates, standing, custody |
| Source projections | exact received artifacts and source coordinates |
| Reader beams | declared reader, prompt/profile, model/runtime, outputs, limitations |
| Candidate structure | claims, relations, boundaries, gaps, alternatives, uncertainty, coverage, rationale |
| Admission receipt | one canonical disposition per item; `rewrite_admit` carries rewritten text and may carry a qualification note |
| Admitted record | compiler-authoritative semantic input |
| Normal form | canonical renderer-independent object for that record/compiler pair |
| Projection receipts | casting conditions and trace links for every derived view |
| Realizability report | typed internal-law and world-compatibility findings for “does this compile?” |
| As-built evidence | attributable observations, if supplied and permitted |
| Residual | typed comparison between intended and observed projections |
| Conformance passport | identities, laws, evidence, exceptions, and test results |

### 3.1 Reader and compiler separation

The Reader may propose:

- semantic items;
- relations;
- candidate epistemic types;
- alternative interpretations;
- uncertainty;
- omissions and inaccessible regions;
- provisional source coordinates.

The Reader cannot:

- admit its own output;
- decide ownership or rights;
- acknowledge a Muse;
- close an OPEN relation;
- authorize an Offering;
- publish a Work;
- or change the deterministic compiler law.

The compiler receives only the admitted record. It never reads raw private source material and never selects among Reader candidates.

### 3.2 Item-level OPEN

OPEN is not a decorative state for a whole artifact. It attaches to the smallest honest unit: claim, relation, source coordinate, boundary, candidate, evidence link, residual classification, or permission.

An OPEN item must remain visibly unresolved in every projection that is permitted to reveal it. Rendering must not make it appear settled merely because a closed shape would be prettier.

## 4 · Renderer-independent normal form

The canonical Pinecœne object is not a Three.js scene. It is a typed, versioned normal form from which spatial, temporal, textual, accessible, and recipient-safe projections can be derived.

At minimum it carries:

- semantic nodes and relations;
- epistemic type and standing;
- source and admission references;
- owner decisions and acknowledged lineage;
- OPEN state and typed gaps;
- disclosure ceilings and rights;
- semantic material roles;
- deterministic topology instructions;
- transition and causal order;
- Address loci;
- inspection copy references;
- accessibility anatomy;
- identity hashes and compiler profile.

### 4.1 Identity ladder

Identity is layered rather than collapsed into one convenient checksum:

```text
received-byte hash
→ source-projection hash
→ candidate-set hash
→ admission-receipt hash
→ admitted-record hash
→ semantic identity
→ normal-form identity
→ projection identity
→ expression/performance identity
→ package identity
→ receipt identity
```

Changing presentation does not change semantic identity. Changing admission does.

### 4.2 Deterministic law

Each deterministic stage declares one `compilerProfileId` and one `compilerVersion`.

- A fixed admitted record plus normal-form compiler profile/version produces a stable semantic identity, normal-form identity, and topology.
- A fixed normal form plus `ProjectionOperatorV0_1` and `ApertureGrantV0_1` produces a stable trace-linked projection identity.
- A fixed trace-linked projection plus Expression, Performance, and render profile produces stable render, scene, and replay identities.
- Changing Expression, Performance, camera, viewport, or renderer may change render identity but cannot change semantic identity, normal-form identity, or topology.
- No runtime entropy may alter meaning.
- Timestamps and storage identifiers must not alter semantic identity.

Seeded pseudorandom variation may be used only where the profile declares it and includes its seed in identity.

## 5 · Projection architecture

### 5.1 Projection is an authored operation

A projection is not a neutral renderer export. It is an authored operation that declares:

- source normal-form identity;
- authorizing seat;
- aim and intended audience;
- angle or traversal;
- selected semantic scope;
- order and emphasis;
- requested contact dimension;
- requested disclosure resolution;
- requested permissions;
- known occlusions;
- trace-link policy;
- projection compiler and version.

`ApertureGrantV0_1` computes the lawful effective contact, resolution, and permissions from the request, normal-form and source ceilings, seat, purpose, and Offering authorization. It records all reductions and denial reasons. `TraceLinkedProjectionV0_1` binds the normal form, Operator, and Grant. The system therefore stores these receipts, not merely rendered bytes.

Expression, Performance, camera, responsive layout, and rendering are applied only after `ProjectionOperator → ApertureGrant → TraceLinkedProjection`. They create a `RenderManifestV0_1` and render identity without rewriting projection or Fold identity.

### 5.2 Four independent axes

The earlier aperture ladder is separated into four axes:

| Axis | Question |
|---|---|
| **Contact `d`** | What topological contact is possible: `d0_point`, `d1_path`, `d2_surface`, or a refused `d3_interior_merger` request? |
| **Resolution `r`** | How much semantic and perceptual detail is disclosed? |
| **Permission `p`** | Which canonical actions are granted: view, inspect, replay, retain, compare, return, share, or download? |
| **Seat `s`** | Which authorized human or role is granting the projection? |

These axes are related but not interchangeable. High visual resolution does not imply broad reuse rights. A spatial view does not imply source access. A permission grant cannot exceed the owner, source, or per-part ceiling.

Spatial Fold, temporal Becoming, document, anatomy, and Offering are projection or performance kinds. They are not values of `d`. Under the current candidate profile, an interior-merger request is refused with a trace and yields no interior bytes. Quotation and reuse remain separate future rights conditions and are never inferred from retain, share, or download.

### 5.3 Trace-linked, not reversible

A governed document or view can carry trace links from its claims to the admitted record and source coordinates. This makes it auditable; it does not make projection mathematically reversible.

The correct claim is:

> A trace-linked projection discloses enough provenance to inspect how it was cast. It does not recreate the inaccessible interior or reveal every lawful alternative projection.

### 5.4 Tomography

Multiple independent source projections can constrain a reconstruction more strongly than one. The interface may show:

- agreement across beams;
- beam-specific claims;
- contradictions;
- unsupported regions;
- inaccessible regions;
- alternate candidate structures;
- human decisions that resolved or preserved uncertainty.

Agreement is evidence, not authority. Repetition does not become admission.

## 6 · Residual and reconstruction fidelity

When a case contains an intended projection and attributable as-built evidence, the product can render the gap between them as a typed residual.

Residual states include:

- `satisfied` — supported by the observed projection;
- `altered` — present but materially changed;
- `omitted` — expected under the declared comparison but absent from available evidence;
- `unsupported` — asserted without sufficient evidence;
- `inaccessible` — cannot be evaluated with the permitted evidence;
- `open` — deliberately unresolved;
- `lawful_adaptation` — changed within an explicitly allowed implementation range.

The residual is not a single quality score. It is a source-linked field of differences with declared comparison law.

The interface must distinguish:

- evidence absence from evidence of absence;
- inaccessible from failed;
- lawful adaptation from drift;
- owner-attested observation from machine-observed evidence;
- current state from historical state.

## 7 · Experience design

### 7.1 Object first remains the law

The visitor should encounter the form before the theory. For a Reconstruction Case, the first frame is the Pinecœne at rest with a restrained statement of standing, not a dashboard of extraction results.

Depth appears through purposeful modes:

1. **Fold** — what the admitted object has become.
2. **Becoming** — what admitted causes changed it over time.
3. **Source** — which projections were supplied and what they permit.
4. **Readings** — what each beam proposed and where it disagreed.
5. **Admission** — what the human kept, changed, rejected, or left OPEN.
6. **Projection** — how a document, view, or Offering was cast.
7. **Residual** — how intended and observed projections differ, if applicable.
8. **Passport** — identity, compiler, rights, evidence, exceptions, and conformance.

Modes appear only when the case possesses the required evidence.

### 7.2 Visual grammar

The existing instrument lineage remains valid, but every mark must now carry reconstruction standing.

- **Committed gold:** admitted commitment, owner decision, or governing relation.
- **Evidence blue:** attributable Return or as-built evidence at its exact locus.
- **Cool OPEN light:** unresolved, permeable, or intentionally withheld closure.
- **Neutral edge:** structural capacity, boundary, or non-committed relation.
- **Gap:** visible absence or unresolved topology; never silently filled.
- **Dark field:** concentration, not decorative space imagery.

No ambient particles, stars, glow, motion, or sound may appear without semantic standing.

### 7.3 Motion law

Motion expresses causal transition only:

- admission creates or strengthens lawful Solid;
- changed standing changes material or relation behavior;
- evidence appears at attributable loci;
- OPEN relations refuse false closure;
- Address reorients the whole form without changing topology;
- Expression changes material treatment without changing semantic structure.

Reduced motion presents the same sequence as explicit semantic steps. Sound remains absent from the current public release profile.

### 7.4 Inspector law

Spatial selection and textual inspection are two views of the same semantic reference. Every selectable feature must expose:

- semantic type;
- standing;
- source coordinates permitted at the current aperture;
- admission decision;
- trace links;
- OPEN or exception state;
- relevant rights and disclosure ceiling;
- accessible inspection copy.

The no-WebGL fallback is a lawful projection, not an apology screen.

## 10 · Custody and disclosure

Before any processing, every supplied artifact receives:

- exact filename and media type;
- byte length;
- SHA-256 receipt;
- origin and date received;
- owner/steward statement;
- processing permission;
- disclosure class;
- availability class;
- source-coordinate method;
- known omissions or inaccessible dependencies.

Availability classes are explicit:

- `supplied_exact`;
- `supplied_sanitized`;
- `referenced_not_supplied`;
- `human_attested`;
- `unavailable`;
- `withheld_by_owner`.

Availability is separate from evidence verification, disclosure class, admission disposition, and OPEN standing. An admitted item may remain `owner_private` under a disclosure ceiling. A candidate excluded from the admitted record uses the disposition `withhold_from_record`.

Private material is not copied into a public Git repository merely for convenience. Where repository custody is not lawful, the case stores a hash-bound reference and an honest availability statement.

Rejected, withheld-from-record, pending, and unreviewed candidates must not affect:

- topology;
- scene features;
- motion;
- text projections;
- accessible copy;
- package bytes;
- recipient downloads;
- source maps;
- public or recipient telemetry;
- recipient-side client logs and network responses.

Payload-free owner custody and private Lineage receipts may record that an exclusion decision occurred and may therefore change. They must not copy the excluded semantic payload into the normal form, render, recipient surface, public telemetry, or public evidence.

## 11 · Conformance strategy

### 11.1 Golden identities

The case requires stable vectors for:

- received source bytes;
- each Reader beam receipt;
- candidate structure set;
- admission receipt;
- admitted record;
- semantic identity;
- normal form;
- each governed projection;
- scene and replay;
- Offering package;
- recipient receipt;
- residual and Passport.

### 11.2 Invariance laws

Tests must prove:

- rejected/withheld-from-record/pending/unreviewed candidates change none of the admitted outputs;
- Expression does not change topology;
- Address does not rewrite the Fold;
- timestamps do not change semantic identity;
- OPEN never closes through rendering;
- multiple renderers preserve the same semantic references;
- a trace link never grants broader source access than the projection permits;
- recipient packages contain no owner-only material;
- Reader agreement does not become admission;
- changing a Reader candidate without changing admission does not change the normal form;
- changing admission changes the relevant downstream identities;
- a residual is reproducible from its declared inputs and comparison law.
- a realizability report separates internal-law result from world-compatibility result;
- unsupported marks, projection/object confusion, OPEN conditions, and inaccessible evidence retain distinct source-linked findings.

### 11.3 Visible Passport

The Passport should tell an informed visitor:

- what the object is;
- what source projections were available;
- which Reader beams ran;
- who admitted what;
- what remains OPEN or inaccessible;
- which compiler and projection profiles were used;
- which identities bind the result;
- what evidence exists;
- what the current standing is;
- what this case does not prove.

## 12 · Delivery gates

The future implementation sequence is gated, not a continuous overnight rewrite.

### R0 · Documentation alignment

- v0.7 system amendment recorded;
- v0.4 approach recorded;
- bounded next-steps record created;
- no application changes.

### R1 · Example intake and qualification

- receipt metadata and exact hashes recorded;
- custody and permissions classified without presuming content-reading authority;
- content inspected only where Deniz has explicitly authorized inspection;
- Reader or model processing deferred unless separately authorized;
- bounded question proposed from permitted material;
- case eligibility assessed;
- proposed Reconstruction Envelope returned to Deniz.

### R2 · Owner case decision

- Deniz accepts, amends, or rejects the proposed envelope;
- private/public boundary fixed;
- Reader beams, model use, and source processing explicitly authorized;
- intended outputs fixed.

### R3 · Contract and fixture freeze

- minimum interfaces derived from the accepted case;
- golden input receipt frozen;
- identity ladder frozen;
- no visual implementation before structural conformance passes.

### R4 · Exact geometry and case instrument

- normal form compiler implemented;
- deterministic Fold and Becoming implemented;
- source, reading, admission, residual, and Passport inspectors implemented;
- desktop, mobile, keyboard, reduced-motion, and no-WebGL states verified.

### R5 · Projection and passage

- at least one trace-linked document/view generated;
- governed Offering built from the same normal form;
- exact Preview/Witness parity proven;
- bounded local Return demonstrated.

### R6 · Protected case acceptance

- exact Preview deployment;
- privacy and disclosure audit;
- cross-browser and accessibility acceptance;
- case-specific conformance receipt;
- Deniz acceptance recorded separately from technical readiness.

### R7 · Optional public release

- sanitization and publication decision;
- route and manifest amendment;
- public copy and design acceptance;
- immutable deployment promotion;
- rollback retained and live result independently verified.

Only R0 is authorized by the present request. Supplying the example begins metadata receipt, byte hashing, and custody classification only. Content inspection, semantic processing, Reader/model runs, admission preparation, implementation, and publication each require the authority stated at their later gates.

## 13 · Design rule for the next conversation

When the example arrives, we do not immediately draw a beautiful object around it.

We first determine:

1. what exact projection was supplied;
2. which interior it may lawfully evidence and which it cannot;
3. what question reconstruction is meant to answer;
4. what multiple readings could genuinely add;
5. which acts require Deniz or another human owner;
6. what can remain OPEN without weakening the case;
7. whether world-facing evidence supports a residual;
8. what the smallest complete demonstration would be.

Then geometry earns the right to appear.
