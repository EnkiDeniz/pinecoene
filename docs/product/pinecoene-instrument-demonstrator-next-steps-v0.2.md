The previous plan waited for a real protected reconstruction case and put source reading, Reader execution, and admission inside the Pinecœne workstream. That is no longer the product boundary.

The next step is a synthetic, local Pinecœne Instrument Demonstrator. Œdit work proceeds independently until both teams are ready to exercise the file seam.

---

## 1. Immediate decision requested

Deniz and the team review and return changes or approve the following direction:

1. Pinecœne receives structured meaning; it does not read raw sources.
2. The first proof uses a synthetic four-point fixture.
3. Candidate, fixture Fold, and recipient projection are separate wire objects.
4. Expression may be radical but cannot alter meaning.
5. Aperture removes material before recipient geometry/rendering.
6. Return remains external and Successor receives a new identity.
7. The first build is local internal only and does not replace production.

Approval of the product direction is not implementation authorization. An implementation plan will separately bind branch, baseline, exact fixture hashes, allowed diff, verification, and rollback/non-production boundary.
