### PCN-RET-002 · Record/source disclosure can leak through derived projections

### PCN-RET-003 · Resolution, replay, and Return are conflated

Current R-level package behaviour and interface language do not form a coherent independent-axis contract. Replay material may travel at ranks whose language does not match it, while Return is separately permissioned.

Required future law: contact, resolution, replay/time, response, permission, seat, identity, source, and assets remain explicit independent axes. R0–R5 are presets only.

### PCN-RET-004 · Unknown Witness identifiers fail open

The inspected route can resolve an unknown server-side identifier to a convenient PCN-0002 fixture.

Required future law: unknown, corrupt, mismatched, colliding, or unsupported package identity fails closed and reveals no unrelated artifact.

### PCN-RET-005 · Return lineage is not exact

Browser-local Return disposition/docking is not strictly bound to the current originating Offering, fixture, or study.

Required future law: every Return binds one exact Encounter package hash and may attach or enter Successor review only through the matching artifact lineage.

### PCN-RET-006 · Current Successor is a marker, not a compiled new object

The current demonstration can write lineage metadata without compiling a new admitted/fixture record and normal-form identity.

Required future law: a Successor has a new work identity, exact predecessor link, eligible Return reference, authority/fixture receipt, and newly compiled normal form. The predecessor remains unchanged.

### PCN-RET-007 · Governing wire schemas are missing

The inspected executable contains legacy validation for earlier Offering/archive formats but not the new candidate, admitted, normal-form, Aperture, or trace-linked recipient contract family.

Required future law: every wire boundary validates exact schema, version, discriminator, references, canonical bytes, and full hashes before persistence or rendering.
