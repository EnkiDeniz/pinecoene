## What this candidate implements

The public hierarchy is now object-first:

`Door → Genesis → Becoming → Studio → Offering → Locket → Encounter → local Return`

Genesis is the Door and the only published Work. The Genesis Chat is an honest curation note. The Thin Fold remains visibly owed. Pinecœne, Becoming exists only on `/next` as an OPEN current study. Studio remains available contextually as the owner instrument; the Locket is explicitly the downstream consent and transport vessel.

The implementation does not create a sentence receiver, arbitrary upload, AI Reader, account system, cloud custody, real delivery, cross-device Return, successor publication, live Œdit link, sound, analytics, or telemetry.

## Custody and disclosure

- Governing recipient packages use `packageKind: recipient_offering` and `packageVersion: pinecoene.offering-package.v0.1`.
- R0–R5 monotonically determine disclosure; Studio no longer presents arbitrary permission switches that conflict with resolution.
- A local owner must explicitly confirm the right to offer the exact Address and projection. Changing Address, Expression, or resolution invalidates that confirmation and any compiled Preview.
- Ajv validation runs on server/build paths. Client paths use CSP-safe structural validation and recompute the canonical SHA-256 package hash before custody or rendering.
- Hosted acquisition is neutral until the exact package resolves. Local/hosted collisions, storage denial, corrupt hashes, stale registry revisions, unsupported packages, and unknown IDs fail closed.
- Dexie migration V3 adds governing recipient packages and portable-transfer receipts without rewriting studies or legacy archives.
- Local Returns are labelled demonstrations. They cannot become Muses or successors and may only be deleted locally.
